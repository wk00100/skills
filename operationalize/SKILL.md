# Operationalize：形容詞 → 行為規格

## 前提

一份文件有兩種讀者：

- **WHY 層**給人讀——負責動機與脈絡，該是敘事的，不動。
- **操作層**給執行者讀——AI 或壓力下的自己，負責消除「所以我現在到底要做什麼」的歧義，全部轉換。

形容詞是高變異 token（「冷漠」每次被展開的樣子都不同），行為規格是低變異 token（「已讀 >4 小時才回、回覆 <10 字」每次都一樣）。

## 轉換規則

1. **形容詞 → 可觀察行為**
   「態度冷漠」→「已讀後 >4 小時才回、回覆 <10 字、不用表情符號」

2. **判斷 → 觸發條件＋動作＋上限**
   「不要過度理解」→「動手前理解時間上限 15 分鐘，超過即開工」

3. **程度詞 → 數字或標準**
   「常常」→「每週 ≥3 次」；「有進步」→「反芻時間從 X 分鐘降到 Y 分鐘」

4. **弱化詞 → 刪掉，或補上它蓋住的事實**
   對象：「本來就」「根本」「只是」「顯然」「當然」「其實」「單純」。
   判準：**把這個詞刪掉，句子還成立嗎？**
   - 成立 → 純贅字，刪。（「只是預填建議值」→「預填建議值」）
   - 不成立 → 它在替一個該寫出來的事實佔位，補事實。（「法規本來就不需要休息」→「法規在 4 小時以內回 0」，讀者可打開 `getOverBreakTime` 對照）

   同組再多修一層：**說話者判斷 → 領域狀態**。「根本不能申請加班」→「不具加班申請資格」——後者對得回後端的拒絕條件，前者只是作者的語氣。

5. **標記不轉換區**
   `## 背景`、`**Why:**`、比喻與敘事段落原文保留，只轉換行動句與標準句。

## 不要轉換的東西

- 已經是可執行標準的柔軟句：「練完想不想再摸一下」是一條二元測試，轉成量表反而變糟。
- 轉換對象只有**無法驗證的形容詞與程度詞**，不是所有感性的句子。

## 程式碼註解

審查或改寫程式碼註解時，加讀 `references/code-comments.md`（讓註解簡潔、清晰、一致的額外標準）。

## 輸出

- 直接產出改寫後的文件，不逐處加註解、不解釋每個修改。
- 交件前自檢：每句行動句至少含「觸發條件／動作／可驗證標準」其中之一；WHY 區塊與原文 diff 為零。
