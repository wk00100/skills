# Operationalize：讓文件不用猜

## 前提

一份文件有兩種讀者：

- **WHY 層**給人讀——負責動機與脈絡，該是敘事的，不動。
- **操作層**給執行者讀——AI 或壓力下的自己，負責消除「所以我現在到底要做什麼」的歧義，全部轉換。

形容詞是高變異 token（「冷漠」每次被展開的樣子都不同），行為規格是低變異 token（「已讀 >4 小時才回、回覆 <10 字」每次都一樣）。

歧義有兩個來源，兩邊都要處理：**說得不夠具體**（A）與**用字沒對準語意**（B）。

## A. 形容詞 → 行為規格

1. **形容詞 → 可觀察行為**
   「態度冷漠」→「已讀後 >4 小時才回、回覆 <10 字、不用表情符號」

2. **判斷 → 觸發條件＋動作＋上限**
   「不要一直卡在同一個 bug」→「同一個假設試 3 次沒進展就換假設，30 分鐘沒進展就問人」

3. **程度詞 → 數字或標準**
   「常常」→「每週 ≥3 次」；「有進步」→「同類問題被 review 退回的次數從每週 5 次降到 1 次」

4. **弱化詞 → 刪掉，或補上它蓋住的事實**
   對象：「本來就」「根本」「只是」「顯然」「當然」「其實」「單純」。
   判斷標準：**把這個詞刪掉，句子還成立嗎？**
   - 成立 → 純贅字，刪。（「只是預填建議值」→「預填建議值」）
   - 不成立 → 它在替一個該寫出來的事實佔位，補事實。（「法規本來就不需要休息」→「法規在 4 小時以內回 0」，讀者可打開 `getOverBreakTime` 對照）

   同組再多修一層：**說話者判斷 → 領域狀態**。「根本不能申請加班」→「不具加班申請資格」——後者對得回後端的拒絕條件，前者只是作者的語氣。

## B. 用字 → 依語境選字

一個原文詞不對應一個固定中文詞。鎖死成一譯就是翻譯腔。

1. **抓可疑詞**：三道檢驗命中任一即換——複合詞被砍成自造縮寫（判準←判斷標準）、字面直翻（程式碼衛生←code hygiene，該說「整理」）、中文連帶意涵比原文重或窄（權威←authoritative、強壯←robust）。
2. **判語意再選字**，別回填同一個字：`authoritative` 強調可信就選「可信來源」，強調官方認定選「官方文件」，強調 source of truth 選「主要依據／基準」，強調地位與定論才選「權威」。
3. **允許同詞多譯**：同一原文詞在不同句依語意給不同中文，這是正確不是不一致。

## 不轉換區

`## 背景`、`**Why:**`、比喻與敘事段落原文保留，只處理行動句與標準句。

## 不要做的事

- 已經是可執行標準的柔軟句不要動：「改完自己願不願意再讀一次」是一條二元測試，轉成量表反而變糟。
- 用詞已符合語境不要動：「權威」用來指不容爭議的定論就是對的。
- 對象只有**無法驗證的形容詞與程度詞**、**可疑且重複出現的固定對應**。不是所有感性的句子，也不是把正式詞全改成白話冗長。

## 程式碼註解

審查或改寫程式碼註解時，加讀 `references/code-comments.md`。

## 輸出

- 直接產出改寫後的文件，不逐處加註解、不解釋每個修改。
- 交件前自檢：每句行動句至少含「觸發條件／動作／可驗證標準」其中之一；每個被改的詞都能講出「原文這裡強調 X，所以選 Y」；WHY 區塊與原文 diff 為零。
