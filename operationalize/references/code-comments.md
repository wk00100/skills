# 程式碼註解

全域指令「Comment 撰寫規則」是基本規則，本檔只補審查與改寫既有註解時用到的部分。SKILL.md 的 A 與 B 照用。

## 改寫前先驗證事實

A 與 B 只處理表達，預設原文的事實正確。原註解的因果寫錯時，規格化會補上版本號、換成更肯定的語氣，把錯的話講得比原文更可信，也更難被下一個人質疑。改寫前先打開註解指涉的對象核對：manifest 欄位、lockfile、被呼叫的函式本體。核對不到來源的斷言不改寫成更具體的版本，標為待查或刪掉。

案例：原註解寫「@nuxtjs/i18n 9.5.4 與 ui-module 都把 vue-i18n 綁在自己的依賴樹」，讀 `node_modules` 下的兩份 package.json 才知道 ui-module 是 `peerDependencies: "*"`（跟著宿主的版本，不會自己帶一份），需要 vue-i18n 11 的套件是第三個套件 shared-lib。只看原註解改寫，改幾輪都還是錯的。

## 破例註解的寫法

設定檔裡的破例（依賴版本 override、白名單、關掉預設檢查）只回答兩題：為了什麼加，什麼條件可以解除。

- 第一題寫衝突的事實，寫出套件名與 range，讓讀者能自己打開 manifest 對照。機制推演、現象敘事、陷阱提示都不寫。
- 第二題只有暫時性破例才回答。答不出解除條件的破例屬於常態設定，不是 workaround，用一行寫清楚原因即可（pnpm 的 `minimumReleaseAgeExclude` 排除內部套件屬於長期政策，不會因為上游修正而收回）。

分類看性質不看欄位名：`overrides` 底下也有單純統一版本、沒有上游問題要等的條目，該類條目不需要解除條件。

## 註解的存廢與內容

1. **先確認能不能靠命名取代**：改名或抽函式能表達的內容不寫成註解。
2. **模糊詞照樣規格化**：`// 暫時` → 暫時到什麼條件為止，`// hack` → 為何要 hack ＋移除條件，`// 之後最佳化` → 觸發最佳化的門檻。
3. **弱化詞會讓讀者誤判程式能不能刪**：註解的讀者多半正在決定要不要修改註解所在的程式。`// 只是選人彈窗新增列時的初值` 讓讀者把「用途範圍窄」理解成「不重要」，下一個人就會想拿掉，即使該行為是 spec 明文要求。寫**用途邊界**（「用途限於選人彈窗開啟時的預填值」），不寫重要性評價。三個月後的讀者需要約束條件，不需要前一個作者對重要性的看法。

## 寫法與用字

4. **刪註解前先分「結論」與「理由」**：結論通常從程式碼讀得出來，理由讀不出來。`errors 優先於 message` 看 `if (messages.length > 0) return messages` 就知道，「有 errors 時 message 是『驗證失敗』這類概括，蓋不住每一筆內容」才是不能刪的部分。精簡時刪掉理由只留結論，註解就退化成複述程式碼。

5. **文件標籤要用在對應的位置**：`@param` 只對函式參數有效，寫在 interface 上 TS Language Service 不會讀取，hover 欄位看不到說明。型別欄位的說明寫成欄位上方的 `/** */`。標籤寫錯位置不會報錯，只會讓說明從 IDE 消失。

6. **中文註解不照英文語序**：「回傳一個包含使用者的陣列」寫「回傳使用者陣列」。
7. **換行依語意斷**：一行一件事，不按字元寬度折行。口語省略句（「要壓一起壓」）改成敘述句，讀者不必自己補回被省掉的主詞與條件。

## 可以保留的註解類型

只有下列類型可以保留，其餘回到第 1 條，確認能不能靠改名或抽函式取代。

| 類型 | 內容 |
|---|---|
| 法律標頭 | 版權、授權 |
| 意圖 | 某個決定背後的理由，讀者不一定同意但知道當初的考量 |
| 闡明 | 把無法修改的 API 難懂的參數與回傳值改寫成白話（`// a < b`） |
| 後果告誡 | 不照做會發生的後果（`SimpleDateFormat 非執行緒安全，每次新建`） |
| 放大重要性 | 看起來能刪其實不能刪的一行（`trim` 不做會被誤判成另一個 list） |
| 對外 API 文件 | 只在公共 API，同樣禁止湊字數 |

「闡明」最容易被濫用：正確性難以驗證，寫之前先確認沒有其他寫法，寫完再檢查一次與實際行為相符。

## 逐條檢查清單（審查既有註解時）

逐則檢查，命中即改或刪。清單可窮舉，比只靠上方原則容易執行。

| 現象 | 處置 |
|---|---|
| 要讀者去翻別的程式才懂 | 補足或刪 |
| 複述程式碼字面，甚至比程式碼難讀 | 刪 |
| 與程式實際行為對不上 | 過期註解，改或刪 |
| 為了滿足「每個參數都要有 `@param`」而產生的空洞文件 | 刪 |
| 檔頭首行覆述函式名（`fallbackErrorMessage` 上寫「後端沒回可讀訊息時顯示的通用訊息」） | 刪首行，留下面的理由 |
| `TODO` 沒有觸發條件與動作 | 刪。寫得出「locales 補上 5XX 訊息後改用」的才留 |
| 檔頭的修改歷程、作者署名 | 刪，交給版控 |
| 抒發情緒（`// Give me a break!`） | 刪 |
| 複製貼上沒改到（四個欄位兩個寫 `The version`） | 刪 |
| 可以抽成具名變數或函式取代 | 重構，不留註解 |
| 位置標誌（`// Actions ///////`） | 偶爾用才有效，重複出現就是雜訊 |
| 右大括號後的 `} // while` | 代表函式太長，縮短函式 |
| 被註解掉的程式碼 | 刪 |
| HTML 標記混在註解裡 | 刪，網頁格式由文件產生工具處理 |
| 描述範圍超出函式管轄（函式不設預設值卻寫預設值） | 移到實際設定的位置 |
| 貼整段 spec 內文 | 只標文件編號 |
| 註解本身還需要解釋（名詞對不回任何運算式或識別字） | 拆具名常數，或改寫到對得上 |

分支寫進程式碼之後，原本描述分支的註解就變成複述。註解只留程式碼看不見的部分，例如同一個函式為什麼要接受兩種形狀的輸入。
