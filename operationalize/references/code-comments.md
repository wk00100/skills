# 讓程式碼註解簡潔、清晰、一致

operationalize 的「形容詞 → 可驗證標準」照用；審查程式碼註解額外套這幾條：

1. **先問該不該存在**：好命名 > 註解。註解只補「程式碼講不出的 why」，不覆述 what（`i++ // 加一` 刪掉）。
2. **說 why，不說 what**：解釋動機、取捨、陷阱、非顯而易見的約束，而不是逐行翻譯程式碼。
3. **模糊詞照樣規格化**：`// 暫時` → 暫時到什麼條件為止；`// hack` → 為何要 hack ＋移除條件；`// 之後優化` → 觸發優化的門檻。
4. **與 code 同步**：註解與程式碼矛盾時，過期註解是負債——標出來，要嘛改要嘛刪。
5. **不留註解掉的死碼**：版本控管記得住歷史，註解掉的程式碼直接刪。
