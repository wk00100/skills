# 程式碼註解

SKILL.md 的 A（形容詞→標準）與 B（依語境選字）照用；註解額外套這幾條。

## 該不該有、說什麼

1. **先問該不該存在**：好命名 > 註解。註解只補「程式碼講不出的 why」，不覆述 what（`i++ // 加一` 刪掉）。
2. **說 why，不說 what**：解釋動機、取捨、陷阱、非顯而易見的約束，而不是逐行翻譯程式碼。
3. **模糊詞照樣規格化**：`// 暫時` → 暫時到什麼條件為止；`// hack` → 為何要 hack ＋移除條件；`// 之後最佳化` → 觸發最佳化的門檻。
4. **與 code 同步**：註解與程式碼矛盾時，過期註解是負債——標出來，要嘛改要嘛刪。
5. **不留註解掉的死碼**：版本控管記得住歷史，註解掉的程式碼直接刪。
6. **弱化詞會誤導「這段能不能刪」**：註解的讀者多半正在決定要不要動這段程式。`// 只是選人彈窗新增列時的初值` 把「用途範圍窄」讀成了「不重要」，下一個人的念頭就是「那能不能拿掉」——即使那是 spec 明文要求的行為。寫**用途邊界**（「用途限於選人彈窗開啟時的預填值」），不寫重要性評價。三個月後讀的人要的是約束條件，不是前一個作者覺得這段重不重要。

## 怎麼寫、用什麼詞

7. **identifier 不翻譯**：變數／函式／型別名、API 名、錯誤字串保留原文。
8. **中文註解也會有翻譯腔**：依中文母語者實際會怎麼講來寫，不要逐字轉英文語序（「回傳一個包含使用者的陣列」→「回傳使用者陣列」）。
9. **概念名與 code 對齊**：註解提到的概念要和 identifier 對得起來，別註解叫「快取」而變數叫 `buffer`。
